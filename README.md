# 📜 GitHub架構個人部落格與雲端同步系統說明書

本專案是一個採用復古牛皮紙風格設計的輕量化個人網誌系統。為了擺脫傳統複雜的主機伺服器與資料庫維護，本系統獨家採用 「GitHub Pages 靜態託管 + 離線純前端管理後台 + JSON 雲端資料同步」，的現代無伺服器（Serverless）架構設計，讓創作者能夠極低成本、極高安全性地隨時發布與管理個人創作。
以下為本系統的十項完整架構與操作介紹：

1. 專案核心架構設計理念
本系統捨棄了傳統 WordPress或動態網誌需要依賴 PHP、MySQL 等繁重後端的架構。前端頁面完全由純 HTML、Tailwind CSS 與原生 JavaScript 組成，所有文章與設定皆收納於單一結構化檔案中，確保網頁載入速度極快，且完美相容於 GitHub 免費的靜態網頁寄存服務。

2. GitHub Pages .倉庫初始化與開通
要讓網誌在網路上運行，首先需在 GitHub 建立一個公開倉庫（Public Repository）。進入倉庫的 `Settings > Pages` 設定頁面，將發布來源（Branch）指定為主分支（通常為 `main`），資料夾選擇 `/ (root)` 並儲存。等待一分鐘系統自動編譯後，即可透過專屬網址存取你的線上部落格。

3. 子目錄路徑與靜態資源對應
若你的倉庫名稱並非對應根網域（例如網址帶有 `/my-blog/` 子目錄），系統內的所有資源與連結（包含 `index.html`、`atom.xml` 訂閱源與各項內部跳轉）皆需正確對應相對或絕對路徑，確保瀏覽器在讀取時不會發生 404 找不到檔案的錯誤。

4. 離線端 `admin.html` 後台運作機制
管理後台設計為一個完全獨立的 `admin.html` 檔案。你不需要將後台檔案上傳到伺服器執行，只需將它下載並保存在本機電腦中，直接用滑鼠雙擊即可透過任何瀏覽器離線開啟，具備極高的隱私性與資安防護。

5. 後台視覺風格與操作介面
管理後台延續了前台溫潤的復古牛皮紙美學（#faf3e0 暖色底與墨褐色字體），並提供直覺的介面供創作者編寫文章、設定文章分類、調整側邊欄小工具順序，以及發布網站最新公告彈跳視窗，操作體驗流暢直覺。

6. 核心資料源 `blog-data.json` 結構
本系統的所有動態內容（包含部落格標題、文章陣列、瀏覽次數、自訂小工具與公告）全部集中記錄於一個名為 `blog-data.json` 的 JSON 檔案中。它扮演了整個網站的「虛擬資料庫」角色，讓前後端資料交換變得極為單純。

7. 前端非同步資料載入與渲染
當訪客打開部落格首頁或點擊特定文章時，前台的 `index.html` 會透過 JavaScript 的 `fetch` 非同步技術，即時向 GitHub 倉庫抓取最新版本的 `blog-data.json` 內容，並動態渲染出最新的文章列表、觀看次數與側邊欄排版。

8. 留言板流量最佳化與手動載入機制
為了防止訪客隨意點擊或大量重新整理導致第三方留言板（如 Graphcomment）的讀取量超出免費額度限制，系統特別將留言板改為「按鈕觸發式」。訪客必須親自主動點擊「展開留言板」按鈕後，才會載入留言腳本，有效節省非必要的流量消耗。

9.  RSS / Atom 訂閱源整合
為了方便讀者追蹤最新動態，系統內建了標準的 `atom.xml` 訂閱檔案。透過側邊欄精美的復古訂閱小卡與正確對應的鏈結，任何標準的 RSS 閱讀器都能無縫抓取你的最新文章更新，建立屬於你自己的忠實讀者圈。

10. 編輯、匯出與雲端更新完整實務流程
當你完成新文章創作時，標準的日常維護流程如下：

步驟一：在本機開啟 `admin.html` 完成文章編輯並點擊儲存，系統會自動導出更新後的 `blog-data.json` 檔案。
步驟二：登入 GitHub 網站，將該 JSON 檔案直接拖曳上傳至專案倉庫根目錄覆蓋原檔案。
步驟三：等待 GitHub Pages 自動部署完成（約 1 分鐘），重新整理網頁即可完美同步上線！
